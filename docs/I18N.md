# Vietnamese and English language support

Updated **27 October 2026**.

Vietnamese (`vi`) is the default for new workspaces. English (`en`) remains available in **Cài đặt → Ngôn ngữ → Lưu cài đặt** / **Settings → Language → Save preferences**. An existing saved language choice is respected.

## Architecture

- `src/i18n/messages/vi.json` and `en.json` contain matching UI message resources, including interpolation and validation/error copy. Resources use stable source-text keys plus semantic keys for richer formatting. Components call `useI18n()`; they do not contain separate Vietnamese translation branches.
- `src/i18n/core.ts` provides pure translation, English/key fallback, enum labels, calendar/time/duration formatting, validation localization and request-language negotiation.
- `src/i18n/provider.tsx` supplies locale context, sets HTML language and metadata, persists the browser preference in `life-os:language` and the `life-os-language` cookie, and localizes native form-validation messages.
- The Next.js root layout reads only the language cookie for its initial locale. Personalized records remain in the existing authenticated data flow. Rendering the localized layout uses request-time rendering.
- The saved `preferences.language` remains authoritative for an opened personal/cloud workspace. Settings saves use the existing browser persistence and revision-safe Supabase snapshot path. A new empty account inherits the selected browser language; returning accounts retain their own saved choice. No database migration, RLS bypass or authentication-provider changes are needed.

## Data preservation

Switching language changes presentation and communication. Event IDs, categories/status enums, dates, local clock values, recurrence rules, tasks, meal/workout records and logs are not translated or rescheduled. User-authored titles, notes, food names and exercise names retain the language in which they were entered.

Sample content is translated only when explicitly creating a new demo workspace. Existing user or demo records are never bulk rewritten. Workout and experience enum values such as `Push` and `Beginner` remain canonical stored values, with translated display labels.

Calendar dates use Vietnamese locale formatting, relative dates and full date headings. Durations render as `2 giờ 30 phút`; current activity renders `Còn 25 phút`. Event instants still use the original IANA timezone and scheduling engine. Native date/time picker chrome follows browser/device capabilities; ISO form/storage values are retained.

## Natural language and AI

`src/lib/quick-add.ts` fills reviewed drafts for expressions such as `mai`, `mốt`, `chiều nay`, `tối thứ Sáu`, `7h`, `7h30`, and `4 giờ chiều`. Missing hours or ambiguous spoken hours leave time fields empty and ask for clarification. Nothing is saved by parsing alone.

The Gemini route sends the saved language preference and explicit communication instructions for titles, descriptions, summaries, warnings and questions. It resolves relative planning dates in the user's timezone. Ambiguous spoken hours return a clarification question before calling Gemini; provider clarification responses also produce no events. The proposal preview/acceptance and constraint checks remain in place. New meal suggestions can use Vietnamese dish names; existing names are never automatically translated.

## Verification

The automated checks cover:

- Resource/key coverage, interpolation, fallback and missing-key safety.
- Vietnamese date/time/duration formatting without altering saved records.
- Natural-language clock/date parsing and ambiguity rejection.
- Language included in authenticated cloud saves and restored for returning accounts.
- Vietnamese default, Vietnamese ↔ English switching, reload persistence and preserved event/task/workout/meal/log values.
- Full existing English acceptance flows.
- Seven main views and dialogs at 375, 390, 768, 1024 and 1440 px; no document horizontal overflow.
- AI clarification and language context through route tests/provider fixtures.

Final results: strict TypeScript and production build passed; **67 unit/API tests and 26 production browser tests passed**. Both message files have **742 matching keys**. Representative Vietnamese screenshots are in `docs/previews/`.

Run `npm run typecheck`, `npm test`, `npm run build`, and `npm run test:e2e` with a local server running. `tests/e2e/life-os.spec.ts` explicitly seeds English preferences for regression coverage; `tests/e2e/i18n.spec.ts` tests fresh Vietnamese defaults and both-language transitions.

Live Supabase email sign-in and real Gemini responses still require configured credentials. Browser/provider test doubles do not establish live service behavior. Physical iPhone/Safari and OS notification delivery need device acceptance testing.

## Maintaining translations

Edit both JSON resource files together. Interpolation names must match. The resource-generation source is `scripts/i18n-translations.tsv`; English overrides and semantic message defaults are in `scripts/build-i18n-resources.mjs`. Run that generator when changing the TSV, then run the unit suite. The inventory/migration/refinement scripts are one-time development records, not application startup steps and should not be rerun on an already migrated component.
